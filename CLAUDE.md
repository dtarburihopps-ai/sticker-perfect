# Правила работы над проектом Sticker Perfect

## Обращение
- Каждое сообщение начинать со слова «Даша,» — затем текст ответа.
- Обращаться к пользователю по имени: Даша.

## Как работать
- Пользователь — начинающий разработчик (~1 месяц опыта). Объяснять технические решения простым русским языком.
- Сначала простой план, потом код. Не делать больших изменений без объяснения.
- Не добавлять библиотеки без необходимости. Не усложнять архитектуру.
- Не переписывать рабочий код ради «красоты».
- Если что-то можно проверить вручную в браузере — сначала проверяем так.
- **Перед любой визуальной частью — сначала показать картинку.** Прежде чем писать или менять код, который Даша увидит глазами (экран, стикеры, сцена, меню, анимация), нарисовать мокап, показать его в чате и спросить: «показать, как это будет выглядеть?» / «оно?». Код трогать только после подтверждения. Цель — чтобы она понимала по картинке, а не читала код туда-сюда.
- Шаги маленькие, каждый сразу проверяем. Ничего не писать «на будущее» — только то, что нужно прямо сейчас.
- Автотестов не пишем. Всё проверяется руками в браузере и глазами.
- После каждого крупного шага коротко сообщать, что получилось.
- Не придумывать за пользователя: если чего-то не хватает в ТЗ — спросить.
- Если не согласен с решением — прямо сказать и аргументировать, а не молча выполнять.

## Ограничения проекта
- Git используем локально, как страховку: коммит после каждого рабочего шага. На GitHub ничего не публикуем — репозитория там пока нет.
- Цель — маленький playable MVP за очень короткое время (~5 часов работы за неделю).
- При выборе «сложно и красиво» vs «просто и очень приятно» — всегда второе.

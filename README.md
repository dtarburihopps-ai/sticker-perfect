# Sticker Perfect

Маленькая игра про наклейки для Telegram Mini App. Берёшь наклейку из полосы внизу, кладёшь на место — она долетает и приклеивается со звуком. Всё.

Играть: **https://dtarburihopps-ai.github.io/sticker-perfect/**

Замысел игры, механики и описания уровней — в [CONTEXT.md](CONTEXT.md). Здесь только про то, как с этим работать.

## Запустить у себя

```bash
python serve.py
```

Дальше открыть http://localhost:8080. Обычный `python -m http.server` тоже сработает, но наш сервер вдобавок запрещает кеш: после правки страница всегда свежая, и не приходится гадать, почему изменения «не применились».

Полезные адреса при разработке:

| Адрес | Что делает |
|---|---|
| `?level=fridge` | открыть уровень сразу, минуя меню |
| `?debug=1` | включить сообщения в консоли (держится при переходах) |
| `?slots=1` | показать места на сцене — нужно, когда расставляешь координаты |

## Из чего состоит игра

Обычные `<script>` в правильном порядке, без сборки, без npm, без модулей. Порядок подключения — он же порядок зависимостей: каждый следующий файл опирается на предыдущие.

| Файл | Что внутри |
|---|---|
| `log.js` | отладочные сообщения |
| `levels.js` | **сами уровни — данные, а не код** |
| `blur.js` | заглушки на время загрузки, делается скриптом |
| `progress.js` | порядок уровней, прогресс, переходы между экранами |
| `sound.js` | звук, синтезируется в коде, без файлов |
| `assets.js` | заглушки и загрузка следующего уровня наперёд |
| `geometry.js` | вся математика: где что лежит и какого размера |
| `rules.js` | что можно, что нельзя, когда уровень собран |
| `game.js` | сцена, сборка уровня, тапы игрока, полёт стикера |
| `menu.js` | альбом с уровнями |

Главное решение проекта: **уровень — это данные**. Движок один, а новый уровень — это новая запись в `levels.js`.

## Команды

```bash
python tools/optimize.py
```

Пережимает картинки: `images/` → `web/`. Запускать каждый раз, когда в `images/` легла новая картинка, иначе в игре её просто не будет. Заодно делает превью для меню и заглушки в `blur.js`.

```bash
node tools/check.js
```

Сверяет данные уровней: место, ждущее несуществующий стикер, забытый `rank`, непережатая картинка и прочее, что не ломает загрузку, а тихо ждёт, пока игрок ткнёт пальцем. Запускается сам при публикации — не сходится, игра на сайт не едет.

```bash
python tools/fridge.py     # и door.py, pencils.py, buttons.py, vending.py
```

Пересчитывает геометрию уровня: режет картинки и печатает готовые строки для `levels.js`. **Числа в `levels.js` руками не правятся никогда** — только через эти скрипты. Рядом лежат `cover.py` и `stickers0.py` — то же самое для вступления, и `grid.py` — линейка поверх фона, когда координаты снимаются с новой картинки.

## Две папки с картинками

- `images/` — оригиналы, тяжёлые PNG. Их режут скрипты из `tools/`. Игра туда не заглядывает, на сайт они не уезжают.
- `web/` — то, что игрок реально качает: те же картинки в WebP и ровно того размера, каким они видны на экране. Делает `tools/optimize.py`.

Путь в `levels.js` всегда ведёт в `web/`.

## Как публикуется

`git push` в `main` — и всё. GitHub Actions прогоняет сверку данных, собирает папку и заливает на Pages. Никаких туннелей и ручных выгрузок.

Телеграм любит кешировать: если сразу после публикации мини-апп выглядит сломанным, закрой его и открой заново.
